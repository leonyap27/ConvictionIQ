## Summary

This ticket was a structured review of the app generated by Lovable — no new features were built. The output is a written gap report (`docs/gap-report.md`) that documents what the app already contains, what it does not need, and what cloud dependencies must be removed before the app can run independently.

---

## What exists today

All five screens required by the prototype are already present in the codebase:

| Screen | What it does |
|---|---|
| Daily Screen | Ranked table of tickers with scoring, filters, and signal indicators |
| Study Card | Detailed analysis drawer that opens from a Daily Screen row |
| Daily Briefing | Portfolio health summary — new setups, improved/weakened signals, exit alerts |
| Recommendation Memory | Filterable history of saved recommendations with a monitoring log |
| Portfolio Exposure | Add/remove holdings and track sector allocation |

A separate Settings screen is not needed — the portfolio screen covers all user-configurable data, and scoring rules are fixed by design for this prototype.

---

## What needs to change before the app is self-contained

The Lovable platform wired four categories of cloud services into the app. None of these belong in a local, single-user tool. They need to be removed in follow-up work before the app can run without internet dependencies or third-party accounts:

| Dependency | What it is | Impact of keeping it |
|---|---|---|
| Lovable AI Gateway | A cloud AI service used to answer natural-language stock questions | App requires a Lovable account and API key to function |
| MCP server (Lovable Cloud) | A remote tool server that Lovable used to connect Claude to the app | Adds unnecessary HTTP endpoints and cloud coupling |
| Supabase sync | A cloud database used to sync app data between sessions/devices | App data currently has an unneeded cloud copy path; sync buttons appear in the header |
| Lovable error reporting | Platform telemetry that sends error events to Lovable's systems | App silently phones home on errors |

Removing these four categories will make the app fully local — no third-party accounts, no cloud calls, data stays in the browser.

---

## Next steps

Four removal tickets are recommended as the immediate next items:

1. Remove the MCP server infrastructure and the Lovable AI Gateway connection.
2. Remove Supabase sync and simplify the app header to remove the Sync/Refresh buttons.
3. Remove Lovable error reporting; replace with a simple local error log.
4. Remove leftover Lovable auth routes (minor cleanup, can bundle with item 1).

Once these are done, the app will be a clean, locally-runnable prototype with no external dependencies.
